# Simulador

O Simulador é uma cópia reduzida do HubSaúde que roda na sua máquina. Ele responde como o ambiente real, inclusive nas exigências de segurança, o que permite testar autenticação e envio de ponta a ponta sem depender de credenciais de produção. Quem instala e controla é o [HubSaúde CLI](cli.mdx).

:::warning

**Os dados não sobrevivem ao reinício.** O Simulador guarda tudo apenas em memória, então parar e subir de novo devolve o ambiente limpo. Ele escuta em HTTPS na porta `8443`.

:::

<Link id="uso" />

## Ciclo de vida {#utitle}

```bash
hubsaude sim start
hubsaude sim status
hubsaude sim stop
```

A porta pode ser alterada com a variável `HUBSAUDE_SIMULADOR_PORT`. Veja as [variáveis de ambiente](cli.mdx#ambiente).

## O que o Simulador reproduz {#qtitle}

Não se trata de uma versão simplificada: o Simulador reproduz a mesma mecânica descrita nas páginas de fluxo.

### Descoberta

Os mesmos endereços de descoberta que os SDKs consultam para localizar o servidor de autorização.

### Emissão de token

Exige certificado de cliente e prende o token emitido a ele, exatamente como a produção faz. Veja [Cache e mTLS](../fluxos/autenticacao.mdx#cache-mtls).

### Envio de recursos

Os endereços `/fhir/*` respondendo no mesmo modelo de envio em duas etapas. [Veja como funciona o envio](../fluxos/envio-recurso.mdx#assincrono).
