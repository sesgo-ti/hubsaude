Ferramentas

HubSaúde CLI

Um único programa instala e comanda tudo o que você precisa para testar a integração antes de ir ao ar: validação de recursos, simulador e servidor FHIR local. Ele não exige Java instalado nem permissão de administrador.

instalar-hubsaude-cli.sh HubSaúde CLI
Instalar com um comando Baixa o hubsaude, confere a integridade por SHA-256 e instala sem exigir administrador nem sudo
$curl -fsSL https://raw.githubusercontent.com/sesgo-ti/hubsaude/main/install.sh | bash
No Windows o comando roda no PowerShell. Em macOS e Linux é preciso ter curl e bash. Opções de versão e diretório →

Comandos

Estes são os comandos do dia a dia. Todos partem do programa hubsaude instalado acima.

ComandoO que faz
hubsaude validate <arquivo>Valida um recurso FHIR R4 a partir de um arquivo
hubsaude validate --dir <dir>Valida todos os recursos de um diretório
hubsaude validate -Lê o recurso da entrada padrão (stdin)
hubsaude validate --output json|webSaída em JSON ou na interface web interativa
hubsaude validate --profile <url>Valida contra um perfil específico
hubsaude validate server status|stopConsulta ou encerra o serviço local do Validador
hubsaude sim start|status|stopCiclo de vida do Simulador SMART on FHIR local
hubsaude server start [--reset]Sobe o servidor HAPI FHIR local; --reset zera os dados
hubsaude server stopEncerra o servidor HAPI FHIR local
hubsaude auth verifyDiagnóstico de credenciamento, detalhado abaixo
hubsaude statusAgrega, numa única invocação, o estado dos três componentes com ciclo de vida (validador, simulador e server)
hubsaude update --checkVerifica se há versão mais recente disponível
hubsaude versionExibe a versão do CLI e dos componentes provisionados

O Validador e o Simulador têm páginas próprias, com exemplos de uso de cada um: Validador e Simulador.

Credenciamento

hubsaude auth verify

Assim que o credenciamento é aprovado, este comando confirma em segundos que a sua chave e o seu certificado realmente funcionam, sem precisar escrever uma linha de código. Ele existe para conferência: para obter tokens no funcionamento normal da aplicação, use um dos SDKs.

hubsaude auth verify \
    --client-id hs-12345678 \
    --key minha-chave.pem \
    --cert meu-certificado.pem \
    --ig hemograma --ig-versao 0.0.1
ExitSignificadoAção recomendada
0Sucesso: token obtido, credencial aptaNenhuma
3Erro de uso: argumentos, arquivos ou configuração inválidosCorrigir a invocação
4Falha de rede: teste inconclusivo (descoberta, timeout, 429, 5xx)Repetir mais tarde (retry/backoff)
6Credencial não apta: rejeição definitiva (HTTP 400/401 invalid_client ou handshake mTLS)Acionar o processo de credenciamento

Na dúvida, o comando erra para o lado seguro. Se a falha não puder ser atribuída com certeza à credencial, ela é classificada como 4, ou seja, inconclusiva. Uma credencial nunca é declarada inapta sem evidência clara. Os mesmos códigos de saída valem para a ferramenta Java autônoma hubsaude-cliente-cli ↗.
